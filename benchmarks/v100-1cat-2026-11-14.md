# V100: 1Cat-vLLM PR experiments

## Result

The exact prompt scorer was 1.25–1.44x faster in component runs. Its scores
were bit-identical. It is opt-in and does not replace the daily profile's
faster, different-rounding SIMT scorer.

An NVFP4 split-K experiment saved 8.3% in a real-weight component run. It
did not establish a full-model improvement over the existing default.
That experiment was removed from the engine.

## Hardware and build

- Two Tesla V100-PCIE-16GB cards, 175 W. GPU0 has PCIe Gen3 x4; GPU1 has x16.
- Ryzen 5 3600. The model runs used both cards with split 16.
- CUDA 12.8.93, NVIDIA driver 580.178.04, Release build for sm_70.
- Branch base: `ee96b35ef`. The experimental model binary SHA256 was
  `2db847c163d606e5c2cba6addfc056ece9870071d5a38e9a21b73d221e4c7a27`.
- The service was stopped during each isolated batch and started afterward.
  Its configuration and installed engine were not changed.

## Open PR survey

The survey used GitHub's open PR list, then read the focused proposals.
Numbers below refer to `1CatAI/1Cat-vLLM`, not Strata.

| Proposal | Applicability and decision |
| --- | --- |
| [#1176: shared QSA scoring and query tiles](https://github.com/1CatAI/1Cat-vLLM/pull/1176) | Eight-query key sharing already existed here. Adapted query tiling to the existing shuffle-reduced exact scorer, which previously handled only short decode batches. Kept the faster eight-query arm; removed the slower four-query arm. |
| [#1384: fast routed experts](https://github.com/1CatAI/1Cat-vLLM/pull/1384) | Its one-PRMT signed selector fits three-magnitude IQ2 codebooks, not IQ3_XXS's eight magnitudes plus sign. The current staged IQ3 path already removes packed sign subtraction. No speculative IQ3 port was retained. This conclusion is static analysis, not a GPU performance measurement. |
| [#1385: instruction-diet experts](https://github.com/1CatAI/1Cat-vLLM/pull/1385) | Depends on #1383/#1384 and their IQ1_M/IQ2_XXS/IQ2_XS formats and DeepSeek geometry. Not copied into the daily IQ3_XXS path. |
| [#1030: FP4 skinny split-K choices](https://github.com/1CatAI/1Cat-vLLM/pull/1030) | Tested the analogous split choices in Strata's existing NVFP4 W4A16 kernel, including 8, 12, 16 and 20 gate/up warps and smaller down splits. Component winner did not beat the existing full-model default. |
| [#959: original-byte IQ3_XXS banks](https://github.com/1CatAI/1Cat-vLLM/pull/959) | Targets vLLM's expanded canonical carrier. Strata's native kernels already consume the packed GGUF blocks. No duplicate storage format was added. |

## Exact scorer component comparison

GPU0, 256 queries, capacity 262,144 cells. CUDA-event timing, 20 repetitions
per process. Six samples per arm, ordered 0/1/2/2/1/0 in three batches.
The table reports medians, not the benchmark's within-process arrow:
on sm_70 without SIMT that arrow compares the scorer with a copy of itself.

| Live cells | Existing exact scorer | Eight-query halve | Four-query experiment |
| ---: | ---: | ---: | ---: |
| 32,768 | 0.825 ms | 0.659 ms | 0.7145 ms |
| 131,072 | 3.527 ms | 2.4885 ms | 2.947 ms |
| 200,000 | 5.6305 ms | 3.9155 ms | 4.5055 ms |

Each candidate passed 138,898,872 bitwise score comparisons across 12 cases.
Those cases include uneven query tiles, partial causal blocks, large
magnitudes and ties. The benchmark's separate FP64 gate is skipped when
its tensor-core scorer is unavailable; that is not the bitwise evidence.

Reproduce the retained route with the existing runners:

```sh
cmake -S . -B build-1cat -G Ninja -DSTRATA_ENABLE_CUDA=ON \
  -DSTRATA_EXPERIMENTAL_SM60=ON -DCMAKE_CUDA_ARCHITECTURES=70 \
  -DCMAKE_BUILD_TYPE=Release -DSTRATA_BUILD_TESTS=ON
cmake --build build-1cat --target qsa_scores_parity qsa_select_bench strata -j4
CUDA_VISIBLE_DEVICES=0 ctest --test-dir build-1cat \
  -R '^qsa_scores(_prompt_halve)?_parity$' --output-on-failure
CUDA_VISIBLE_DEVICES=0 STRATA_SELECT_SIMT=0 STRATA_SCORES_THREAD=0 \
  STRATA_SCORES_PROMPT_HALVE=0 build-1cat/qsa_select_bench 131072 256 20 262144
CUDA_VISIBLE_DEVICES=0 STRATA_SELECT_SIMT=0 STRATA_SCORES_THREAD=0 \
  STRATA_SCORES_PROMPT_HALVE=1 build-1cat/qsa_select_bench 131072 256 20 262144
```

Compare the first `scores` time across processes. Keep the GPU idle.
`STRATA_SELECT_SIMT=1|2` takes precedence at the prefill call site.
`STRATA_SCORES_THREAD=1` also takes precedence. No default was changed.

## NVFP4-QAD experiment

Used the existing QAD pack on disk, not a new download or repack.
The component runner read ten distinct real experts and timed 1,000
six-row grouped calls after 50 warmups. Three samples per setting:

| QPN2 gate/up / down split | Median per grouped call |
| --- | ---: |
| Automatic: 10 / 10 warps | 109.0 us |
| 8 / 10 | 99.9 us |
| 12 / 10 | 112.3 us |
| 16 / 10 | 107.6 us |
| 20 / 10 | 107.2 us |
| 10 / 5 | 109.8 us |
| 10 / 8 | 109.6 us |
| 20 / 5 | 108.7 us |

The 4-row and 8-row real-weight split sweeps each reported zero failed
checks. Output error against the double reference was 1.085% and 1.099%,
respectively. The component's shared destination-row layout is not a
full engine window. Its timings are only a candidate-selection signal.

The actual model comparison retained the measured production tuning:
whole-expert RAM arena, 524288 logical context, int8 elastic KV, MTP 4,
minimum draft probability 0.7, 800 MiB reserve, lazy-vision reservation,
HC_Q8, resident routing and the existing verification cap. Both arms
used the same experimental binary. QPN2 changes the arithmetic against
the default expert path. A same-process split choice changes FP32
reduction order, not weight values.

Eight processes ran in this order: default, QSA no-op, QPN2 auto, QPN2
8-warps, QPN2 8-warps, QPN2 auto, QSA no-op, default. Each had two
uncached 2,048-token prompts with a 512-token output cap. Default and
QSA no-op processes also had two 32,768-token prompts. The QSA arms
retained `STRATA_SELECT_SIMT=1`: logs confirmed the new scorer was not
reached. Their timing differences are noise, not gains.

| 2,048-token actual-model arm | Median decode | Generated tokens per sample |
| --- | ---: | --- |
| Existing default experts | 94.74 tok/s | 512, 512, 191, 512 |
| QPN2 automatic split | 91.46 tok/s | 512, 512, 512, 354 |
| QPN2 8-warp gate/up | 92.33 tok/s | 512, 512, 512, 512 |

All eight processes completed without harness errors. QPN2 route messages
were present only in the QPN2 arms. No thermal slowdown samples were
recorded. Decode varied between samples; the short completions remain
in the raw data. This is not a quality benchmark or proof of a small
throughput difference. It provides no evidence for replacing the existing
default with QPN2 or shipping a split override on this machine.

## Final retained-build verification

The final CUDA build passed both scorer CTests: 2/2. A separate QAD
model smoke explicitly set `STRATA_SELECT_SIMT=0` in both arms. Each
process read two uncached 32,768-token prompts and generated 64 tokens.
The candidate's route message appeared only with the switch enabled.

| Exact scorer model smoke | Prefill tok/s, first / second prompt |
| --- | ---: |
| Existing warp scorer | 1266.37 / 1274.17 |
| Tiled halve scorer | 1271.79 / 1280.07 |

One process per arm is not enough to claim a model-throughput gain.
One of the two full replies matched token for token; the other did not.
Bitwise scorer parity does not establish whole-model determinism under
the existing resident routing and verification cap.

A direct component comparison confirmed why the daily profile was left
alone: its SIMT scorer took 0.238 / 0.916 / 1.433 ms at 32K / 131K / 200K,
against the exact candidate's 0.707 / 2.633 / 3.953 ms in the same runs.
All three FP64 accuracy gates passed. Selected IDs matched for 256/256,
256/256 and 255/256 rows. SIMT is faster but has a different summation
order; it is not the exact scorer's replacement when bitwise scores
are required.

After restoring the unchanged daily service, an authenticated HTTP smoke
returned `17` for `9 + 8`, with finish reason `stop`. An initial 32-token
request had exhausted its output cap during reasoning and returned only
`1`; the complete check used a 128-token cap and zero reasoning budget.
No server reasoning default was changed.
